# 입법예고 의견 자동 분류

국회입법예고에 시민이 남긴 법안 의견을 분류 기준(코드북)에 따라 LLM으로 자동 분류하고, 사람이 직접 분류한 표본과의 일치율로 품질을 쟀습니다. 리서치 실무의 자유응답 코딩을 자동화하는 실험입니다.

| 항목 | 값 |
|---|---|
| 의견 | 공개 의견 **1,843건**(법안 4개, 법안당 의견 번호 무작위 500건 중 공개된 것) |
| 분류 틀 | 찬반 3값 + 주제 **9개**(코드북 v3, 법안 공통) |
| 주제 일치율 | **0.70**(Cohen's κ 0.61) — 아무도 보지 않은 평가 표본 50건, 95% 구간 0.57～0.83 |
| 찬반 일치율 | **1.00** — 평가 표본 두 개 모두 50/50 |
| 사람 자기 일치도 | 주제 0.90 — 같은 50건을 하루 뒤 다시 단 결과(LLM 일치율의 상한 역할) |
| 비용 | 전체 분류 API 정가 환산 **$7.28**(실제 청구 없음, 아래 "LLM 호출") |

출처: 열린국회정보(진행중/종료된 입법예고), 국회입법예고, 조회 2026-10-15

자세한 결과와 한계는 [보고서](outputs/report.md)에 있습니다.

## 무엇을 알게 되었나

- 공개 의견의 **56%가 이유 없이 찬반만** 밝혔다(15자 이상에서도 36%)
- 이유가 있는 의견은 법안마다 주된 주제가 다르다 — 국가보안법 폐지안은 안보·체제, 정보통신망법은 권리·자유, 소득세법은 공정·형평·권리·경제적 부담, 공인중개사법은 효과·필요성과 공정·형평
- **LLM이 어긋난 의견을 다시 읽으면, 사람이 같은 꼴의 의견에 때마다 다른 라벨을 단 경우가 많았다.** 코드북 문장은 LLM이 더 일관되게 따랐다
- LLM 확신도가 "높음"인 의견은 사람과 잘 맞고(0.86～1.00), "낮음"인 의견은 사람도 다시 달 때 흔들렸다(자기 일치도 0.50) → 확신도로 사람이 다시 볼 의견을 고를 수 있다
- 코드북 v1 → v3의 차이는 50건 표본에서 우연과 구분되지 않았다

## LLM 호출

- Claude Code 명령줄(`claude -p`)을 의견마다 실행한다. 지시문은 코드북 1～6절 그대로, 출력은 JSON 스키마(찬반·주제·근거 구절·확신도)로 강제한다. 도구·MCP를 끄고 빈 폴더에서 실행해 다른 지시가 섞이지 않게 했다
- 작성자의 Claude 구독 안에서 돌아 실제 청구는 없다. 비용 칸은 명령줄이 알려 주는 API 정가 환산액이다(`outputs/llm_runs.csv`)

## 실행

Python 3.14, Claude Code 명령줄(로그인된 상태), 열린국회정보 인증키가 필요합니다.

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env          # ASSEMBLY_API_KEY를 채운다

.venv\Scripts\python src\collect_bills.py        # 법안 목록
.venv\Scripts\python src\collect_opinions.py     # 의견 본문(4개 법안 × 500건)
.venv\Scripts\python src\clean.py                # 정제·15자 기준
.venv\Scripts\python src\review_sample.py        # 검수 표본 → 라벨 시트
.venv\Scripts\streamlit run src\label_app.py     # 사람 라벨
.venv\Scripts\python src\classify.py --model sonnet --sheet all   # 전체 분류
.venv\Scripts\python src\agreement.py --model sonnet --codebook v3 --split eval2
.venv\Scripts\python src\build_db.py             # SQLite·집계
.venv\Scripts\streamlit run src\dashboard.py     # 대시보드
```

## 데이터와 개인정보

- 열린국회정보 이용약관·Open API 이용약관을 따랐다. 의견 작성자 이름·아이디는 처음부터 받지 않았고, 본문 속 전화번호·이메일·주민번호 패턴은 저장 전에 지웠다(검사 결과 0건)
- **의견 원문은 작성자의 저작물이라 저장소에 올리지 않았다.** `data/`와 `outputs/raw/`는 올리지 않고, 공개한 것은 건수·비율·일치율뿐이다. 코드북과 문서의 예시는 모두 지어낸 문장이다
- 결과는 "의견이 어떤 주제로 나뉘는가"까지다. 특정 정당·의원·법안을 평가하지 않는다. 의견을 남긴 사람은 국민 전체를 대표하지 않는다

## AI와 함께 일한 방식

코드·분석은 Claude Code와 함께 했고, 판단은 작성자가 했다. 단계마다 AI가 한 것 / 작성자가 정한 것 / AI가 틀린 것과 잡은 방법을 [AI 활용 기록](docs/AI_활용_기록.md)에 남겼다.

- 작성자가 정한 것: 데이터·법안 선택, 짧은 의견 기준, 코드북 구조, 같은 문안 처리, 모든 사람 라벨, 모델 선택, 코드북 규칙(문맥 기준), 다시 달기·새 평가 표본 결정
- AI가 틀려서 고친 예: 코드북 v2에 넣은 규칙이 v1 규칙과 부딪힌 것을 놓침 → 사람 다시 달기 결과에서 발견해 v3에서 고침
