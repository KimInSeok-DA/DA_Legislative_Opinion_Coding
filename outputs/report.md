## 2. 무엇을 했나

1. 열린국회정보 Open API로 22대 입법예고 법안 20,274건 목록을 받고, 의견이 많은 법안 중 소관 위원회가 다른 4개를 골랐다
2. 국회입법예고 사이트에서 법안당 의견 번호 500개를 무작위로 골라 본문만 받았다(작성자 정보는 받지 않음, 요청 간격 1초). 2,000건 중 공개 1,843건
3. 15자 미만 의견은 읽지 않고 "이유 없는 찬반"으로 두었다. 이 기준은 사람이 20건을 확인해 유지했다(이유 있는 의견 1건)
4. 의견 100건을 읽고 코드북 v1을 만들었다. 이 100건과 같은 문안 묶음은 이후 평가에서 모두 뺐다
5. 같은 문안을 조금씩 바꿔 낸 의견을 3글자 조각 겹침(자카드 0.6)으로 묶고, 묶음당 1건씩 검수 표본 100건(개선용 50·평가용 50)을 뽑아 사용자가 직접 라벨을 달았다
6. 개선용 50건으로 모델을 고르고(Sonnet), 어긋난 건을 사용자와 함께 읽어 코드북 v2를 만들었다
7. 평가용 50건을 LLM 결과 없이 다시 달아 사람 자기 일치도를 쟀고, 거기서 나온 규칙 충돌을 고쳐 v3를 만들었다
8. 아직 아무도 보지 않은 묶음에서 새 평가 표본 50건을 뽑아 v1·v2·v3를 같은 조건에서 비교했다
9. v3로 전체를 분류해 SQLite와 집계표로 정리했다

## 4. 품질 — 사람 라벨과의 일치율

### 평가 설계

- 사람 라벨은 저장소 작성자가 직접 달았다. AI가 만든 라벨은 정답으로 쓰지 않았다
- 모델과 코드북은 **개선용** 표본으로만 고르고, 고친 뒤에는 **보지 않은 표본**으로 다시 쟀다
- 평가 표본의 라벨은 LLM 결과를 본 뒤에 고치지 않았다(개선용 라벨 13칸은 고쳤고, 원래 값과 이유를 기록)

### 결과

| 평가 | 코드북 | 찬반 | 주제 정확도 / κ | 주제(이유 없는 찬반 뺀 것) | 이유 있음·없음 |
|---|---|---|---|---|---|
| 개선용 50건(원래 라벨) | v1 | 0.98 | 0.76 / 0.70 | 0.71 | 0.96 |
| 처음 평가용 50건 | v1 → v2 | 1.00 | 0.78 → 0.80 / 0.72 → 0.75 | 0.71 → 0.74 | 0.94 → 0.96 |

- 같은 표본에서 코드북 버전끼리 다르게 분류한 의견은 50건 중 4건뿐이다. 50건에서 0.70의 95% 구간이 0.57～0.83이라 **버전 차이는 우연과 구분되지 않는다**
- 두 평가 표본의 차이(0.80과 0.70)도 표본 50건의 흔들림 범위 안이다
- 모델 비교(개선용 50건, v1): Sonnet 주제 0.76·이유 있음/없음 0.96, Haiku 0.72·0.90

## 5. 무엇을 알게 되었나

1. **어긋남의 상당수는 LLM보다 사람 쪽 적용 차이에서 나왔다.** 세 번의 평가에서 어긋난 의견을 다시 읽으면, LLM이 코드북 문장을 그대로 따르고 사람이 같은 꼴의 의견에 때마다 다른 라벨을 단 경우가 많았다(예: 법안이 국민 재산을 지켜 준다는 말을 처음엔 권리, 고친 규칙으로는 효과로 판단한 것을 다음 표본에서 다시 권리로 담)
2. **사람의 판단 기준은 문맥에 따라 갈리는데, 코드북이 한쪽만 적고 있으면 사람도 헷갈린다.** "악용 우려", 체제 낱말, 물가 상승분 과세는 사용자가 설명한 문맥 기준(무엇에 대한 악용인지, 누가 체제를 흔든다는 것인지, 힘들다는 것인지 남과 비교하는 것인지)을 넣어서야 규칙이 됐다
3. **코드북을 고칠수록 좋아진다고 말할 수 없었다.** 50건 표본에서는 2～4건 차이가 우연과 구분되지 않는다. 사람 자기 일치도(0.90)가 상한 역할을 한다
4. **찬반은 거의 풀린 문제, 주제는 아니다.** 찬반은 두 평가 표본 모두 100%였고, 15자 미만 의견의 찬반 낱말 규칙도 사람 20건과 모두 같았다

## 6. 한계

- **표본이 작다**: 평가 표본 50건씩. 정확도 구간이 ±0.13 정도로 넓다
- **평가자가 한 명이다**: 다른 사람과의 일치도(코더 간 신뢰도)는 재지 못했다. 사람 자기 일치도는 하루 뒤 다시 단 것이라 기억 효과로 높게 나왔을 수 있다
- **대표성**: 입법예고에 의견을 남긴 사람은 국민 전체를 대표하지 않는다. 법안당 의견 번호 500개만 무작위로 받았고 비공개 의견은 빠졌다
- **같은 문안**: 같은 문안을 여러 사람이 낸 경우가 많다. 표본은 묶음당 1건이라 "서로 다른 문안" 기준의 일치율이고, 묶음 크기로 가중한 일치율은 0.71(v3)로 비슷했다
- **비용 표기**: Claude Code 명령줄(`claude -p`)을 구독 안에서 써서 실제 청구는 없고, 명령줄이 알려 주는 API 정가 환산액을 적었다
- **재현성**: 같은 코드북으로 다시 돌렸을 때 결과가 얼마나 흔들리는지 재지 않았다. 모델 이름(`claude-sonnet-5-5`)과 실행 시각은 기록했다
- **원문 비공개**: 의견 원문은 작성자의 저작물이라 저장소에 올리지 않았다. 이 보고서의 예시와 설명에도 원문을 옮기지 않았다
