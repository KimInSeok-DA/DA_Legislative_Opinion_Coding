# 1017_01 코드북 v2와 개선용 라벨 수정

- 상태: **결정(2026-10-17, 사용자)**
- 앞 결정: 1015_03(코드북 v1), 1015_04(개선용 50 / 평가용 50), 1016_01(Sonnet)

## 1. 확인한 사실

- 코드북 v1 + Sonnet, 개선용 50건에서 주제가 어긋난 12건(찬반 1건 포함). 그중 10건은 Haiku도 같은 쪽으로 어긋남 → 모델보다 기준 문제
- 사용자가 12건 원문을 다시 읽고 건마다 왜 그렇게 달았는지 설명했다. 나눠 보면
  - 잘못 읽음 1건(본인 부담 이야기로 읽음)
  - 코드북 규칙과 다르게 단 것 7건: 재산권 보호(법안의 효과) 2, 세금 이야기를 넓게 `burden`으로 1～2, 결과가 권리 문제 1, 정치적 비난 1, 분량이 비슷할 때 먼저 나온 이유 1, 찬반 낱말이 없는 찬성 1
  - 규칙이 없거나 정해야 했던 것 3건: 막연한 효과 말(2건), 결론 문장의 무게(1건), 법안과 무관한 내용이 대부분인 의견(1건)
- LLM은 12건 대부분에서 코드북 문장을 그대로 따랐다. 사람이 코드북을 적용하는 일관성이 LLM보다 낮았던 것이 어긋남의 주된 원인

## 2. 결정

| 물음 | 선택지 | 결정(사용자) |
|---|---|---|
| 막연한 효과 말("부작용이 많을 것", "발전을 기대") | 이유 없는 찬반 유지 / 효과·필요성 | **이유 없는 찬반 유지** |
| 이유가 여러 개일 때 | 가장 많이 말한 것 유지 / 결론으로 내세운 것 | **가장 많이 말한 것 유지** |
| 법안과 무관한 내용이 대부분 | 법안 부분만 보고 판단 / 판단 불가 | **법안 부분만 보고 판단** |
| 나머지 라벨 수정 9칸 | 모두 동의 / 일부 제외 | **모두 동의** |

- 개선용 라벨 13칸(12건) 수정. 원래 라벨·고친 라벨·이유는 `data/labels/relabel_log.csv`, 고치기 전 시트는 `data/labels/review_sheet_original.csv`(모두 비공개)
- 코드북 v2 변경은 `docs/코드북.md` 7절. 주제 9개는 그대로, 판단 규칙과 헷갈리는 경우 표만 보강

## 3. 근거와 감수하는 것

- 규칙은 대부분 그대로 두고 문장을 분명하게 했다. 사용자가 고른 세 규칙 모두 "세기만 하면 되는" 쪽이라 사람과 LLM이 같은 답을 내기 쉽다
- **LLM 답을 본 뒤에 다시 판단했으므로 LLM 쪽으로 끌려갔을 수 있다.** 그래서
  - v1 개선용 일치율은 원래 라벨 기준(0.76)을 그대로 기록한다(`outputs/agreement.csv`의 `labels=original`)
  - 고친 개선용 라벨로 낸 일치율(v1 0.96, v2 1.00)은 코드북을 맞춘 표본이라 **성능 지표로 쓰지 않는다**
  - **평가용 50건 라벨은 고치지 않는다.** v1·v2 비교는 평가용으로만 한다

## 4. 결과 (Sonnet, 평가용 50건, 원래 라벨)

| 지표 | v1 정확도 / κ | v2 정확도 / κ |
|---|---|---|
| 찬반 | 1.00 / 1.00 | 1.00 / 1.00 |
| 주제 | 0.78 / 0.72 | 0.80 / 0.75 |
| 주제(사람 `no_reason` 뺀 31건) | 0.71 / 0.64 | 0.74 / 0.68 |
| 이유 있음·없음 | 0.94 / 0.87 | 0.96 / 0.91 |
| 주제(묶음 크기 가중) | 0.78 / 0.72 | 0.80 / 0.75 |

- v1 → v2 차이는 50건 중 1건이라 **나아졌다고 말할 수 없다**. 같은 코드북으로 다시 돌렸을 때의 흔들림도 재지 않았다
- 확신도 `high`로 낸 건은 v1 25건, v2 24건 모두 주제가 사람과 같았다. `medium`은 0.55·0.68, `low`는 0.67·0.25
- 개선용에서 본 어긋남의 원인이 사람의 적용 일관성이었으므로, 평가용 어긋남 10건에도 사람 쪽 실수가 섞여 있을 수 있다. 평가용은 LLM 결과를 보여 주지 않은 채 다시 다는 방법으로만 확인할 수 있다(열린 결정)

## 6. 사람 자기 일치도 (평가용 50건 다시 달기, 2026-10-17)

- 평가용 50건을 순서를 섞고 번호를 새로 붙여(T001～T050) LLM 결과·이전 라벨 없이 코드북 v2로 다시 달았다(`src/self_agreement.py`). 원래 라벨은 고치지 않는다

| 지표 | 사람1 ↔ 사람2 | LLM(v2) ↔ 사람1 | LLM(v2) ↔ 사람2 |
|---|---|---|---|
| 찬반 정확도 / κ | 1.00 / 1.00 | 1.00 / 1.00 | 1.00 / 1.00 |
| 주제 정확도 / κ | **0.90 / 0.87** | 0.80 / 0.75 | 0.82 / 0.77 |
| 주제(이유 없는 찬반 뺀 것) | 0.84 / 0.79 | 0.74 / 0.68 | 0.80 / 0.74 |

- 주제: 셋 다 같음 39, 사람끼리만 같음 6, LLM이 사람1과만 같음 1, 사람2와만 같음 2, 셋 다 다름 2
- 사람끼리 어긋난 5건 중 4건이 정치적 의도가 낀 경계(안보·효과와)
- LLM 확신도별 사람 자기 일치: high 0.96(24건), medium 0.91(22건), low 0.50(4건) → LLM이 확신이 낮은 의견은 사람도 흔들린다
- 사람끼리 같고 LLM만 다른 6건을 읽어 본 결과(평가용이므로 코드북을 고치는 데 쓰지 않음)
  - LLM이 쓰인 코드북을 따른 쪽 3건: 체제 낱말("공산주의", "자유민주주의")만 있는 정보통신망법 의견을 사람은 두 번 다 안보·체제로 달았다(코드북은 외부 세력이 없으면 정치적 의도·권리), 물가 상승분 과세를 사람은 경제적 부담으로(코드북은 공정·형평), 다른 법안 내용을 잘못 올린 의견을 LLM은 판단 불가로
  - **코드북 안의 모순 1건**: "누가 무엇에인지 없는 악용 우려 → 효과·필요성"(v1부터)과 "막연한 효과 말 → 이유 없는 찬반"(v2 추가)이 부딪힌다. 사람은 두 번 다 이유 없는 찬반
  - 경계 1건: 다른 사건으로 덮지 말라는 말(정치적 의도 / 이유 없는 찬반)
- 해석: LLM은 사람 자기 일치도보다 주제 정확도가 약 0.08～0.10 낮다(50건 중 4～5건). 그 차이의 절반가량은 사람이 일관되게 쓰는 판단이 코드북 문장과 다른 곳이다. 사람 쪽은 하루 만에 다시 달아 기억 효과로 높게 나왔을 수 있다
