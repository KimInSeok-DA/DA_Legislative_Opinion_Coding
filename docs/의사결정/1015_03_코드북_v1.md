## 1. 확인한 사실

### 읽은 의견

- `src/codebook_read.py`: 법안마다 `route=llm` 고유 텍스트를 시드 20261015로 섞어 **1차 15건(초안용)**, **2차 10건(점검용)**을 뽑았다. 4개 법안 합계 100건(고유 텍스트의 8.6%). 원문은 화면에서만 읽고 파일·문서에 옮기지 않았다
- 1차 60건으로 주제 틀을 만들어 고정한 뒤 2차 40건에 대 봤다. 2차에서 막힌 곳은 규칙에 넣었다 → **100건 모두 코드북을 만드는 데 쓴 의견**으로 보고 7단계 검수 표본에서 뺀다
- 법안 맥락: 국회입법예고 법안 페이지 「제안이유 및 주요내용」(`src/bill_summary.py`, 페이지는 `data/raw/bill_pages/`에 저장, 조회 2026-10-15)

### 읽고 알게 된 것 (원문 인용 없이)

1. 이유의 소재는 법안마다 다르지만 몇 가지 틀로 모인다. "국가 권력이 권리·자유를 줄인다"는 정보통신망법(표현·언론)과 소득세법(재산권·거주 이전)에 다 나오고, "발의자·정당의 의도를 문제 삼는다"는 4개 법안 모두에 나온다
2. 정당·이념 표현이 내용 이유와 한 의견 안에 섞인 경우가 많다 → 어느 쪽을 주제로 할지 정하는 규칙이 필요하다(코드북 4절 3번)
3. 15자 이상이어도 찬반 반복·평가 낱말(악법 등)·법안 이름 되풀이만 있는 의견이 많다. AI가 초안을 100건에 대 보니(**정답 아님**) 약 1/3이 "이유 없는 찬반"이었다. 1015_02에서 본 것(20자 이상 의견의 46%에 이유 표지어 없음)과 같은 방향이다
4. 2차 40건 점검(AI가 대 본 것, **정답 아님**): `other`·`unclear`는 0건. 40건 중 13건은 두 주제 사이에서 망설였다
   - 막연한 "부작용·악용 우려"만 있는 의견: 이유 없는 찬반 ↔ 효과·필요성
   - "비민주적" 같은 가치 낱말만 있는 의견: 이유 없는 찬반 ↔ 권리·자유
   - 국가보안법 "보완책 없이 폐지": 안보·체제 ↔ 효과·필요성
   - 이유 여러 개를 한 줄씩 늘어놓은 의견
   - → 코드북 4절 "자주 헷갈리는 것"과 5절 제외 규칙에 넣었다
5. **같은 문안의 변형**이 많다. 핵심 문장이 같고 몇 글자만 다른 의견이 국가보안법 54건(고유 텍스트 30), 공인중개사법 51건(22), 소득세법 42건(14)이다. 문안마다 구절 하나로만 센 것이라 더 있을 수 있다. 고유 텍스트로 뽑아도 같은 문안이 표본에 여러 번 들어갈 수 있다 → 7단계에서 정한다(5절)

## 2. 선택지

### (1) 라벨 구조

| | **A. 법안 공통 틀 (권장)** | B. 법안별 라벨 | C. 공통 대분류 + 법안별 소분류 |
|---|---|---|---|
| 라벨 | 주제 7개(기타 포함) + 이유 없는 찬반 + 판단 불가 = 9개, 4개 법안 공통 | 법안마다 주제 4～6개, 합계 20개 안팎 + 2개 | A의 9개 + 법안마다 소분류 2～4개 |
| 법안 고유 쟁점 | 코드북 6절 "법안별 적용"과 LLM 근거 문장으로 보완 | 가장 잘 보인다 | 소분류로 보인다 |
| 평가용 50건에서 라벨당 건수 | 평균 5건 남짓 | 2～3건 | 대분류는 A와 같고 소분류는 1～2건 |
| 법안 간 비교 | 같은 축으로 비교 | 안 된다 | 대분류로 비교 |
| 사람 검수 | 라벨 9개 하나로 | 법안마다 다른 라벨 | 칸 하나 더 |

B의 예(정보통신망법): 표현의 자유 침해 / 처벌 수위 / 검열·악용 우려 / 정치적 의도 / 허위 정보 피해 예방

### (2) 찬반

- **가. 주제에 섞기**: "반대-권리·자유", "찬성-효과·필요성"처럼 한 라벨로. 칸은 하나지만 라벨이 주제×찬반으로 늘고, 대부분 반대라 빈 라벨이 많다
- **나. 별도 칸 (권장)**: 찬반(찬성·반대·불명) + 주제(단일). 주제 이름은 방향을 담지 않는다("침해"와 "보장"이 같은 `rights`)

## 3. 권장 근거

### A. 공통 틀

1. **검수 표본 크기에 맞는다.** 평가용 50건에 라벨이 20개를 넘으면(B) 라벨당 2～3건이라 혼동표와 라벨별 정밀도·재현율을 읽을 수 없다. 9개도 라벨당 평균 5건 남짓이라, 라벨별 수치는 참고로만 쓰고 전체 일치율·κ를 주 지표로 쓴다
2. **법안 간 비교가 된다.** 대시보드·보고서의 "법안별 주제 비율"을 같은 축에 놓을 수 있다. 법안을 위원회별로 고른 이유(1015_01 근거 2: 같은 틀이 분야가 달라도 통하는지 본다)와도 맞다
3. **실제 이유가 법안을 가로지른다.** 권리·자유, 정치적 의도, 공정·형평은 2개 이상 법안에서 나왔다(1절). 한 법안에 몰리는 주제(안보·체제)도 공통 틀 안에 둘 수 있다
4. **코드북 하나, 프롬프트 하나.** 법안마다 바뀌는 것은 6절 맥락뿐이다. 설명이 쉽고 사람이 외울 라벨이 9개다

- 감수하는 것: 법안 고유 쟁점이 한 주제로 뭉친다(예: 공인중개사법 찬성 이유는 대부분 `effect`로 간다). 보고서에서는 8단계 LLM 출력의 근거 문장으로 구체 내용을 보인다
- C를 바로 하지 않는 이유: 소분류를 사람이 달면 검수 부담이 늘고, LLM만 달면 검증 없이 쓰게 된다. v1 결과를 보고 필요한 법안만 나눈다(4절)

### 나. 찬반 별도 칸

1. **같은 주제가 양쪽 이유로 쓰인다.** 권리·자유는 정보통신망법에서는 반대 이유(표현의 자유 침해), 국가보안법 폐지안에서는 찬성 이유(사상의 자유 회복)다. 효과·필요성도 공인중개사법에서는 찬성 이유(사고 예방), 소득세법에서는 반대 이유(집값 상승)다. 섞으면 한 주제가 두 라벨로 갈라진다
2. **오류를 나눠 볼 수 있다.** 찬반 일치율과 주제 일치율을 따로 재면 LLM이 찬반에서 틀리는지 주제에서 틀리는지 구분된다. 섞으면 한 라벨에 두 오류가 겹친다
3. **규칙 쪽 573건도 같은 칸에 들어간다.** 15자 미만 "이유 없는 찬반"도 찬반은 있다. 찬반 칸이 따로면 공개 의견 1,843건 전체의 찬반 분포를 낼 수 있다(규칙 쪽은 낱말 규칙, 8단계에서 정함)
4. **빈 라벨이 줄어든다.** 3개 법안은 "반대" 낱말이 93～97%라 주제×찬반 라벨은 대부분 비어 있게 된다

- 감수하는 것: 사람이 칸 2개를 단다. 찬반은 대개 첫 문장에 있어 시간이 크게 늘지 않는다

### 주제 수가 예상(8～12개)보다 적은 이유

- 실제 의견을 읽어 보니 내용 주제 5개 + 정치적 의도 + 기타로 2차 40건이 모두 들어갔다(`other` 0건)
- 더 쪼갤 후보(예: `effect`를 "시장 영향"과 "피해 예방·필요성"으로)는 경계가 겹친다("집값 안정 목적을 못 이룬다" ↔ "집값이 오른다"). 사람·LLM 모두 헷갈리고 평가 표본의 라벨당 건수도 준다 → 개선용 50건 결과를 보고 v2에서 나눈다
- 처음에는 `effect`를 찬성 쪽 "필요성"과 반대 쪽 "부작용"으로 나눴다가 합쳤다. 방향으로 나누면 "주제에 방향을 담지 않는다"(나안)와 어긋나고, 찬반만 다르게 본 경우에도 주제까지 불일치로 잡힌다

### 여러 이유가 섞였을 때 (코드북 4절)

- **정치적 의도는 내용 이유가 없을 때만**: 정당·이념 표현이 내용 이유와 함께 자주 나온다. "어느 쪽이 주된가"를 매번 판단하면 사람과 LLM이 엇갈린다. 내용 이유를 앞에 두면 판단이 하나로 정해지고, 결과도 "법안 내용의 무엇을 문제 삼는가"를 보여 준다
- **내용 이유끼리는 "가장 많이 말한 것, 비슷하면 먼저 나온 것"**: 고정 순서(예: 안보 > 권리 > …)는 판단은 쉽지만 앞 순위 주제가 부풀려진다. "먼저 나온 것"만 쓰면 지나가듯 말한 이유가 뽑힌다. 그래서 둘을 이었다
- 개선용 50건에서 여러 이유 의견의 불일치가 많으면 v2에서 "먼저 나온 것"만으로 바꿔 비교한다

## 4. 바꾸는 조건 (v2에서 확인)

- 개선용 50건에서 `other`가 5건(10%)을 넘으면 → 새 주제를 만든다
- 한 주제가 한 법안의 "이유 있는 의견"의 60%를 넘고 그 안에 성격이 다른 이유가 섞여 있으면 → 그 법안만 소분류(C)
- 혼동표에서 두 주제 사이 불일치가 전체 불일치의 1/3을 넘으면 → 경계 규칙을 고치거나 두 주제를 합친다
- 찬반 일치율이 주제 일치율보다 낮으면 → 찬반 정의(특히 국가보안법 폐지안의 방향)부터 고친다

## 5. 7단계에 넘기는 것

- 코드북을 만든 100건(`src/codebook_read.py`)은 검수 표본에서 뺀다 → 남은 고유 텍스트 1,061건에서 법안별 25건
- 같은 문안 변형: 고유 텍스트로 뽑아도 같은 문안이 여러 번 뽑힐 수 있다(국가보안법 고유 333건 중 30건). 쉬운 사례가 겹치면 일치율이 부풀려진다 → 변형을 한 묶음으로 보고 묶음당 1건만 뽑을지 7단계에서 정한다
- 라벨 시트 칸: 찬반, 주제, 메모(망설인 이유). LLM 결과 칸은 두지 않는다
