# 1017_02 코드북 v3와 새 평가 표본

- 상태: **결정(2026-10-17, 사용자)** — B. v3를 만들고 아무도 보지 않은 새 표본 50건으로 평가
- 앞 결정: 1017_01(v2, 사람 자기 일치도)

## 1. 확인한 사실

- 평가용 50건 다시 달기에서 사람이 두 번 다 같고 LLM만 다른 6건 중, 사람이 일관되게 쓰는 판단이 코드북 문장과 다른 곳 2개(체제 낱말, 물가 상승분 과세)와 코드북 안의 모순 1개(악용 우려)
- 사용자 설명: 셋 다 **문맥에 따라 갈린다**. 코드북이 한쪽만 적고 있어 헷갈렸다

## 2. 선택지

- A. v2로 전체 분류, 모순은 한계로 적음
- **B. v3 + 새 평가 표본**: 이미 본 평가용 50건으로 v3를 재면 고친 표본으로 평가하는 셈이라, 아직 쓰지 않은 묶음에서 새로 뽑는다

## 3. 결정 (사용자)

| 물음 | 결정 |
|---|---|
| 악용 우려 | "악용될 우려"만 → 이유 없는 찬반. 무엇에 대한 악용인지 있으면 효과·필요성. 누가 무엇에인지 있으면 그 주제 |
| 체제 낱말 | 공산주의 위협에서 체제를 지킨다·공산주의 사회가 된다 → 안보·체제. 특정 정부·정당이 자유민주주의를 흔든다는 비난 → 정치적 의도 |
| 물가 상승분 과세 | 그 때문에 힘들다·"고려하지 않는다"만 → 경제적 부담. 다른 사람·자산과 비교해 불공평 → 공정·형평 |

- 코드북을 고치다 찾은 충돌: 정보통신망법 6절 "민주주의·자유에 반한다 → 권리·자유" → 공산주의 체제로 가는 위협을 말하면 안보·체제라는 예외를 붙임
- 지난 버전 코드북은 `docs/코드북_버전/`에 보관(v1은 git의 main, v2는 v3 변경을 되돌려 복원, v3는 현재와 같음). `src/classify.py --codebook v2`로 지난 버전을 같은 표본에 돌린다

## 4. 새 평가 표본 (`src/eval2_sample.py`, 시드 20261017)

- 처음 표본과 같은 묶음(3글자 조각 자카드 0.6)에서 코드북을 만들 때 읽은 묶음 93개와 이미 쓴 100묶음을 빼고 남은 810묶음 → 법안별 12·13·12·13묶음 × 묶음당 1건 = 50건
- 확인: 묶음 번호가 처음 표본 때와 같음(쓴 100건의 묶음이 모두 일치), 기존 표본과 같은 텍스트 0, 시트 안 중복 0
- 시트 `data/labels/eval2_sheet.csv`(E001～E050), 의견 번호·묶음은 `eval2_key.csv`(비공개)
- 사용자가 라벨을 다는 동안 Sonnet으로 v1·v2·v3를 모두 돌려 두었다(사용자에게는 보이지 않음). 정가 환산 $0.42·$0.44·$0.46

## 5. 결과 (새 평가 표본 50건, Sonnet)

- 사용자 라벨: 주제 이유 없는 찬반 18, 안보·체제 11, 효과·필요성 8, 권리·자유 8, 공정·형평 2, 정치적 의도·기타·경제적 부담 각 1. 찬반 반대 42, 찬성 8. 메모 2

| 지표 | v1 정확도 / κ | v2 정확도 / κ | v3 정확도 / κ |
|---|---|---|---|
| 찬반 | 1.00 / 1.00 | 1.00 / 1.00 | 1.00 / 1.00 |
| 주제 | 0.66 / 0.56 | 0.62 / 0.52 | **0.70 / 0.61** |
| 주제(사람 이유 없는 찬반 뺀 32건) | 0.63 / 0.52 | 0.63 / 0.52 | 0.66 / 0.56 |
| 이유 있음·없음 | 0.82 / 0.61 | 0.80 / 0.54 | 0.86 / 0.69 |
| 주제(묶음 크기 가중) | 0.67 / 0.57 | 0.64 / 0.53 | 0.71 / 0.62 |

- v1·v3가 다르게 단 의견은 4건뿐이다. v3가 v1보다 2건 더 맞았지만 50건에서 정확도 0.70의 95% 구간은 0.57～0.83이라 **버전 차이는 우연과 구분되지 않는다**
- 처음 평가용(0.80)보다 낮다. 두 표본 모두 50건이라 표본 간 차이도 이 범위 안이다. 새 표본은 100자 넘는 의견이 24%(처음 표본 19%)
- 확신도 `high`의 주제 정확도 0.86(29건), `medium` 0.53(19건), `low` 0/2
- 어긋난 15건을 읽어 본 결과(이 표본도 이제 본 표본이므로 코드북을 고치는 데 쓰지 않음)
  - **권리 낱말 한마디(4건)**: 권리 침해를 법안 이름처럼 한마디로만 붙이거나 수사적 질문으로만 말한 것을 사람은 이유 없는 찬반, LLM은 권리·자유로 달았다. 코드북은 "짧아도 무엇이 어떻게 되는지 있으면 이유"라 LLM 쪽이다
  - **사용자가 앞서 정한 규칙과 다른 라벨(3건)**: 막연한 효과 말(업계 발전, 국민에게 해롭다)을 효과·필요성으로(1017_01 결정은 이유 없는 찬반), 법안이 국민 재산권을 지켜 준다는 말을 권리·자유로(1017_01에서 효과·필요성으로 고침)
  - 코드북 문장과 다른 라벨 2건(정보통신망법이 민주주의 원칙에 어긋난다는 말 → 사람 안보·체제, 형법으로 대체 가능 → 사람 기타 이유), 이유가 여럿인 긴 의견 3건, 경계 3건
- 해석: 세 번의 평가에서 LLM은 **코드북에 적힌 규칙을 사람보다 일관되게 적용**했고, 어긋남의 상당수는 사람이 같은 꼴의 의견에 다른 라벨을 단 데서 나왔다. 코드북을 더 고쳐도 사람 쪽 일관성(자기 일치도 0.90, 기억 효과 포함)이 상한이 된다
