# 1015_04 검수 표본과 같은 문안 변형

- 상태: **결정(2026-10-15, 사용자)** — B. 묶음당 1건 + 읽은 묶음 제외, 기준 0.6, 규칙 쪽 법안별 5건
- 앞 결정: 1015_02(15자 기준, 규칙 쪽 20건 확인), 1015_03 5절(코드북을 만든 100건 제외, 같은 문안 변형은 7단계에서 정함)
- 데이터: `route=llm` 고유 텍스트 1,161건(`data/interim/opinions_clean.csv`), 코드북을 만들 때 읽은 100건(`src/codebook_read.py`의 `read_sample()`)

## 1. 확인한 사실

### 같은 문안을 묶는 방법 비교

같은 법안 안에서만 비교했다. "글자 조각"은 공백·기호를 뺀 텍스트에서 연속 3글자씩 잘라 낸 조각이다. 두 의견의 조각 집합이 얼마나 겹치는지(겹치는 조각 수 ÷ 둘 중 하나라도 가진 조각 수, 자카드 유사도)를 재고, 기준 이상인 쌍을 이어서 묶는다(A~B, B~C가 비슷하면 A·B·C가 한 묶음).

| 방법 | 묶음 수(국가보안법·소득세법·공인중개사법·정보통신망법) | 2건 이상 묶음 | 가장 큰 묶음 |
|---|---|---:|---:|
| 공백·기호만 빼고 완전히 같은 것 | 321 · 280 · 255 · 271 | | |
| 글자 조각 겹침 0.5 이상 | 280 · 258 · 175 · 243 | 39개(텍스트 244) | 45 |
| **글자 조각 겹침 0.6 이상** | 291 · 267 · 194 · 251 | 37개(텍스트 195) | 26 |
| 글자 조각 겹침 0.7 이상 | 297 · 270 · 221 · 260 | 32개(텍스트 145) | 25 |
| 글자 조각 겹침 0.8 이상 | 299 · 271 · 232 · 262 | 27개(텍스트 124) | 23 |

- 고유 텍스트 수는 333 · 287 · 267 · 274
- 쌍을 구간별로 무작위로 읽어 보았다(원문은 화면에서만)
  - 0.6 이상: 읽은 쌍이 모두 같은 문안이었다. 긴 이유 문안에 띄어쓰기·맞춤법·앞뒤 찬반 한 마디만 다른 것, 그리고 "○○ 법안에 찬성합니다" 꼴의 짧은 찬반 문장끼리
  - 0.5～0.6: 대부분 같은 문안이지만, 서로 다른 두 문안을 한 의견에 이어 붙인 텍스트를 다리 삼아 다른 문안끼리 한 묶음이 된 경우가 있었다(공인중개사법)
  - 0.6 미만에도 같은 문안이 있다: 같은 이유 문안 앞에 자기 문장을 길게 덧붙이면 겹침이 0.4～0.5로 떨어진다. 이어 묶기 때문에 상당수는 중간 변형을 거쳐 같은 묶음에 들어간다
- **완전 일치만으로는 거의 못 잡는다**(1,161 → 1,127). 변형 대부분이 띄어쓰기·문장부호 외에 낱말이 조금씩 다르다

### 코드북을 만든 100건의 변형이 남아 있다

- 0.6 기준으로, 읽은 100건과 같은 묶음에 속한 **나머지 텍스트가 99건**이다(정보통신망법 5, 공인중개사법 **58**, 국가보안법 24, 소득세법 12)
- 읽은 100건만 빼면 공인중개사법은 남은 텍스트의 약 1/4이 코드북을 만들 때 본 문안의 변형이다 → 평가가 "코드북을 만든 의견으로 평가하지 않는다"(1015_03)를 어기게 된다

### 고유 텍스트를 그냥 뽑으면

- 읽은 100건을 뺀 고유 텍스트에서 법안별 25건을 무작위로 2,000번 뽑아 보니, 25건 중 같은 묶음끼리 겹치는 의견이 평균 0.5～2.7건(공인중개사법 평균 2.7, 최대 10)
- 같은 문안이 여러 번 들어가면 한 번 맞히거나 틀린 것이 여러 번 세어진다. 같은 문안은 사람도 LLM도 같은 라벨을 다는 쉬운 사례라 일치율이 부풀려진다

### 규칙 쪽(15자 미만)

- 573건, 같은 텍스트를 빼면 국가보안법 35 · 소득세법 55 · 공인중개사법 75 · 정보통신망법 67

## 2. 선택지

### (1) 같은 문안 변형

- **A. 고유 텍스트 그대로**: 가장 단순하다. 같은 문안이 표본에 겹치고, 코드북을 만든 문안의 변형이 평가에 들어간다
- **B. 묶음당 1건 + 읽은 100건의 묶음 통째로 제외 (권장)**: 글자 조각 겹침 0.6 이상으로 묶고, 읽은 100건이 속한 묶음은 빼고, 남은 묶음에서 법안별 25묶음을 뽑아 묶음마다 1건을 무작위로 고른다
- **C. B + 큰 묶음이 더 잘 뽑히게(크기 비례)**: 실제 의견 수 비중에 가깝지만 뽑는 법과 설명이 복잡해진다

### (2) 묶는 기준

- 0.5: 더 많이 묶지만 서로 다른 문안이 이어 붙은 텍스트를 다리로 섞인다
- **0.6 (권장)**: 읽은 쌍이 모두 같은 문안
- 0.7 이상: 더 깨끗하지만 놓치는 변형이 늘어 (1)의 효과가 줄어든다

### (3) 규칙 쪽 20건

- **같은 텍스트를 뺀 뒤 법안별 5건 무작위 (권장)**. "반대합니다" 같은 같은 문장이 여러 번 뽑히면 이유 있는 의견이 있는지 보는 데 도움이 안 된다

## 3. 권장 근거

1. **평가 표본의 의견 하나하나가 따로 판단한 사례여야 한다.** 같은 문안 10건을 맞히면 판단 한 번이 10번으로 세어진다. 묶음당 1건이면 100건이 100번의 서로 다른 판단이다
2. **코드북을 만든 의견으로 평가하지 않는다.** 1015_03에서 읽은 100건을 빼기로 했는데, 그 변형 99건이 남아 있다. 묶음 통째로 빼야 원래 뜻이 지켜진다
3. **설명이 쉽다.** "공백·기호를 빼고 3글자씩 잘라 조각이 60% 이상 겹치면 같은 문안" — 숫자 하나로 설명되고 결과를 사람이 확인할 수 있다. 임베딩·군집 알고리즘이 필요 없다
4. **표본이 모자라지 않는다.** 0.6 기준, 읽은 묶음을 빼고 남는 묶음이 226 · 171 · 270 · 243이라 법안별 25묶음 + 여유가 있다

- 감수하는 것: 일치율이 "서로 다른 문안" 기준이 된다. 큰 묶음(같은 문안을 수십 명이 낸 것)은 전체 의견에서는 비중이 크지만 표본에서는 1건이다. 9단계에서 **묶음 크기로 가중한 일치율**을 보조 지표로 함께 낸다(묶음 크기를 곱해 더하기만 하면 된다). C를 바로 하지 않는 이유는 뽑는 단계를 복잡하게 하지 않고 평가 단계 가중으로 같은 정보를 얻을 수 있어서다
- 감수하는 것 2: 0.6 미만인 같은 문안은 일부 남는다. 표본을 뽑은 뒤 라벨 시트의 법안별 25건을 눈으로 한 번 더 확인해, 같은 문안이 보이면 그 묶음의 다음 후보로 바꾼다

## 4. 표본 설계 (권장안 기준)

| 항목 | 값 |
|---|---|
| 모집단 | `route=llm` 고유 텍스트에서, 읽은 100건이 속한 묶음을 뺀 나머지 |
| 뽑기 | 법안별 25묶음 무작위 → 묶음마다 1건 무작위(시드 고정) = 100건 |
| 나누기 | 법안마다 개선용 13·12 / 평가용 12·13(법안을 번갈아 합계 50 / 50) |
| 규칙 쪽 | `route=rule` 같은 텍스트를 뺀 뒤 법안별 5건 = 20건, 별도 시트 |
| 라벨 시트 칸 | 번호·법안·텍스트·찬반·주제·메모(LLM 결과 칸 없음), 원문이 있어 `data/labels/`(비공개) |
| 라벨 다는 순서 | 시트는 법안·개선/평가를 섞은 무작위 순서. 어느 의견이 평가용인지 시트에 보이지 않게 따로 저장 |

## 5. 결정

- (1) **B**, (2) **0.6**, (3) **고유 텍스트 법안별 5건**. 4절 설계 그대로. 근거는 3절
- 묶는 방법은 임베딩·LLM 없이 글자 조각 비교만 쓴다(`src/dedup.py`)

## 6. 바꾸는 조건

- 라벨 시트를 확인할 때 한 법안 25건 안에 같은 문안이 2쌍 이상 보이면 기준을 0.5로 내려 다시 뽑는다
- 규칙 쪽 20건에서 이유 있는 의견이 2건 이상이면 1015_02 기준을 낮춘다(1015_02 5절)
